# 2026-11-18 작업 기록 — 현장 관제 대시보드 + 음성 명령

MechDog 4대가 함께 일하는 팀 프로젝트에서 제가 맡은 **Part A: 현장 관제 대시보드와 음성 명령**의 하루 작업 기록입니다.
실제 코드는 팀 저장소(비공개)에 있고, 이 저장소에는 화면 코드와 브라우저 안에서 도는 가짜 로봇 데모를 올립니다.

## 구조

```
[브라우저: 관제 화면 + 마이크(Chrome 음성 인식)]
      │ WebSocket
[대시보드 서버 (Python aiohttp)] ── Gemini API (규칙에 없는 말만)
      │ MQTT
[공정 엔진 · 로봇 4대 (ESP32 MicroPython 브리지)]
```

## 오늘 한 것

| 기능 | 내용 |
|---|---|
| 시연장 접속 | `--web-host 0.0.0.0` 으로 켜면 같은 와이파이의 팀원 기기에서 화면 접속 |
| 지도: 판대기 → 버켓 | 지도 편집기 항목을 U 자 버켓(입구 방향·폭)으로 변경 |
| **음성 지연 측정** | 마이크 열림 → 첫 글자 → STT 확정 → 해석 → 로봇 응답까지 구간별 시간을 화면에 표시하고 기록 |
| **로봇별 음성 명령** | "2호기 멈춰" → 그 로봇만 정지, 나머지는 계속. "1번" = "일번" = "1호기", "1번 2번 멈춰" 는 두 대 |
| STT 오인식 대응 | 실측에서 "1호기" 가 "1억이" 로 10번 중 4번 적힘 → 같은 말로 받음 |
| 오프라인 표시 | 끊긴 로봇에 보낸 명령이 성공처럼 보이던 문제 수정 ("연결 안 됨: 1호기") |
| **넘어짐 경고** | 기울기(roll/pitch) 45° 이상 약 1초 → 노란 ⚠ WARNING 표지판 |
| **LLM: Gemini** | 규칙에 없는 말만 6개 명령(시작·승인·일시정지·재개·정지·상태) 중 하나로 분류. 정지는 항상 규칙 |

## 실측

### 음성 지연 (실제 마이크, Chrome `ko-KR`)

| 명령 | 기준 | 중앙값 |
|---|---|---|
| "1호기 멈춰" | 말 **시작** → 정지 전송 (말하는 도중 바로 보냄) | 0.76 s |
| "1호기 다시 시작" | 말 **끝** → 명령 확정 | 0.12 s |
| 규칙 해석 | 서버 | 1 ms 미만 |

시간 대부분은 브라우저 음성 인식(첫 글자까지 약 0.4 s)입니다. 로봇이 받기까지의 시간은 아직 못 쟀습니다.

### Gemini 해석 (규칙에 없는 말)

| 말 | 결과 | 시간 |
|---|---|---|
| 애들 좀 쉬게 해 | 일시정지 | 1.7 s |
| 자 이제 하던 거 마저 해 | 재개 | 1.0 s |
| 오늘 점심 뭐 먹지 | 명령 아님 | 1.2 s |
| 1호기 좀 쉬게 해 | 1호기만 일시정지 | 0.8 s |
| 로봇들 일하러 보내 | 작업 시작 | 0.8 s |
| 좋아 그대로 가도 돼 | 승인 | 1.0 s |

6/6 정답. `gemini-3.5-flash-lite` 사용 (flash 모델들은 시험 때 서버 시간 초과가 잦았음).

## 배운 것 / 문제

- **음성 명령은 "안전한 쪽으로" 해석한다.** 정지는 LLM 을 거치지 않고 말하는 도중 바로 보내고, 로봇 번호를 못 알아들으면 전체 정지로 처리한다.
- **STT 는 생각보다 자주 틀린다.** 실제로 말해 보고 틀린 표기를 모아 규칙에 넣는 것이 효과가 컸다.
- **보낸 것과 받은 것은 다르다.** MQTT 로 "보냈다" 를 성공으로 세면, 끊긴 로봇도 멈춘 것처럼 보인다 → 연결된 로봇만 센다.
- **Gemini API**: 요청 기한을 10초보다 짧게 주면 400 오류, 이 모델은 thinking MINIMAL 미지원, 무료 키는 빠른 연속 요청 시 429.
- **남은 문제**: 실제 로봇(mechdog-01)이 연결 후 1~3분 만에 끊긴다. 배터리·신호는 정상이라 원인 조사 중.

## 데모에서 해 볼 것

- 음성 칸 입력창에 `2호기 멈춰`, `1번 다시 시작`, `1억이 멈춰` → 그 로봇만 정지·재개, 아래 ⏱ 줄에 지연 표시
- 위쪽 `⚠ 넘어짐 시연` → 3호기가 6초 동안 넘어진 상태 (WARNING 표지판)
- 데모는 규칙만 씁니다 (Gemini 는 API 키가 필요해서 실제 대시보드에서만 동작).
